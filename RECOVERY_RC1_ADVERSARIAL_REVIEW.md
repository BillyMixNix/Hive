# Independent adversarial review of RC1

This record was opened **before** the protected-test boundary was changed. An independent read-only subagent reviewed the RC1 authority path after deterministic preflight; the primary agent separately reproduced the relevant read path with a synthetic sentinel. Findings remain recorded even if a subsequent RC1 adapter change contains them.

| Finding | Evidence | Severity and disposition |
|---|---|---|
| Frozen acceptance source can become model-visible when the exact test file already exists in the baseline | `hive_canonical/legacy/workshop/hive_jvm.py:freeze_junit_tests` accepts an existing same-byte destination; `hive_canonical/legacy/workshop/hive.py:_validate_worker_observation` accepts `read_file_excerpt` for `src/test/java/...`; `hive_canonical/legacy/workshop/hive_context.py:observe` reads it. A model-free synthetic `PRIVATE_FROZEN_SENTINEL` placed at that path was returned by `observe`. | **HIGH, demonstrated conditional leak.** The archived J001 baseline lacks the frozen acceptance file, so the completed J001 preflight was not affected. RC1 must reject host-frozen source embedded in the model-visible baseline before candidate generation. |
| Generic Gradle build scripts may be able to fake a frozen result if host write scope includes the build script | `hive_canonical/legacy/workshop/hive_jvm.py:inspect_gradle_project` pins wrapper/profile but not arbitrary build-script bytes; `hive_canonical/legacy/verification/jvm_runner.py:run_jvm_profile` invokes candidate Gradle and checks JUnit XML, with the frozen source hash checked separately. | **HIGH potential, unproven exploit.** The frozen J001–J004 scopes authorize application Java only, so this does not invalidate their gate. A general RC1 scope allowing a build script needs a separate adversarial verifier qualification; RC1 may fail closed for such scopes until then. No forged PASS is claimed. |
| RC1 result projection initially conflated reviewer-provider unavailability with software failure | `hive_canonical/controller.py:_failure_class` formerly collected `agents.reviewer.failure` as a controller blocker after the deterministic verifier passed. A new deterministic test reproduced the conflation. | **MEDIUM, demonstrated and repaired in the new adapter.** Reviewer disposition remains `unavailable`, deterministic PASS remains PASS, promotion stays unavailable. |
| RC1 result projection initially labeled planner-correction exhaustion as local model runtime failure | Recovered `_run_build_impl` adds a generic `run/agent_call` wrapper to terminal controller exceptions, including rejected planner output. The earlier adapter used that label as runtime evidence. | **MEDIUM, demonstrated and repaired in the new adapter.** RC1 now requires a failed per-call prompt trace before classifying a model runtime failure. |
| Runtime provenance is verified at preflight, not at every candidate call | `recovery/rc1/manifest.py:build` independently checks the recovered blobs and emits a manifest. `hive_canonical/controller.py:produce_candidate` does not rehash its own installed code or config before each call. | **MEDIUM limitation, source-backed.** The clean Git checkout and preflight identify the RC1 source; a later local mutation would require a new preflight. Do not describe RC1 as continuously runtime-attested. |

The independent review also targeted verifier bypass, stale-base overwrite, reviewer override, hidden promotion, path traversal, junction escape, unauthorized writes, incomplete hashing, timeout/cancellation and state resume. Findings without concrete evidence are not treated as established defects. RC1 exposes no promotion method, its copied historical apply entry points are disabled, and it makes no restart/resume claim. The static synthetic verifier tests are not a substitute for a malicious-Gradle execution probe.

**Post-review containment:** `hive_canonical/controller.py:produce_candidate` now rejects any frozen acceptance source already present in the model-visible baseline before candidate staging or worker calls. A deterministic recovery test first demonstrates that the old observation path returns a synthetic sentinel, then confirms the new host check rejects the setup. This narrows RC1 input eligibility without modifying the recovered engine or a frozen test. Runtime-result projection also separates reviewer unavailability and planner correction exhaustion from software verification.

**Preflight validity:** the initial 18-pass recovery result preceded these changes and is superseded. The clean-checkout recovery suite was rerun after containment: 22 passed, 1 skipped; 40-file provenance remained exact. The archived suite and real baseline JUnit preflight retain their observed results because neither ran a candidate with an embedded frozen test or a writable build script. Build-script report forgery remains an unproven general-scope risk requiring a separate adversarial fixture before that scope is considered safe. Runtime self-attestation is not claimed.
