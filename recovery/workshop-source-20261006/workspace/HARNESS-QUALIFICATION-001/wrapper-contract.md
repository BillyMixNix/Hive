# Verifier wrapper equivalence contract

`VerifierRecorder.wrap(original, verifier_kind)` wraps the targeted and full verifier seams identically. It returns the exact object returned by `original(*args, **kwargs)`, including false, empty, null, unexpected fields and malformed fixtures. It performs no result-schema normalization and does not synthesize PASS or FAIL. Hive's existing caller remains responsible for interpreting its production return value.

The original callable is invoked exactly once with the same positional objects and keyword values. Real exceptions, including `TimeoutExpired`, are re-raised with their original object, type and message. A returned timeout report remains that same report; an exception is not converted into a report. Wrapper frames necessarily appear in tracebacks; verifier exception semantics are unchanged.

Candidate reads, private cache creation, Docker/JVM execution, source-integrity checks and verification-result decisions belong to the real production verifier. The wrapper does not change any command, deadline, cache policy, source file, frozen test or verdict. Hive owns staged-edit rollback and full-gate prerequisite decisions.

Measurement-only side effects are append-only event rows, copied input artifacts in a separate evidence directory, copied result/exception metadata, monotonic duration and an in-memory invocation/error ledger. Results are copied before handing them to measurement writers. A failing copy or writer cannot mutate the returned verifier object or replace its exception. Candidate-capture code is read-only toward the candidate.

Ordinary instrumentation exceptions are contained by `_observe` at every fallible measurement step (clock, capture, copy, event and result persistence). They are classified `MEASUREMENT_FAILURE` in memory, independently of the true verifier outcome. A failed writer is not called recursively to record its own failure. The real verifier still runs. An unavailable measurement sink can mean no durable event exists; the separate in-memory ledger must then invalidate scoring. `collect_records` tolerates absent/invalid timings, partial rows and malformed row objects and explicitly reports incomplete measurement. It never indexes missing timing fields or invents a verification verdict.

A cell driver must finish the normal controller call, persist the independent measurement status where storage is available, and refuse scoring/continuation when measurement failed. It must not inject the measurement error into Hive as a verifier exception. Fatal process termination, exhausted memory preventing any Python execution, arbitrary external file mutation, operator interrupts and a permanently hung external writer are outside what an in-process wrapper can guarantee; this qualification does not claim mathematical immunity to those failures. Normal synchronous IO has observation overhead, and equal timings are not required.

The original defect is eliminated by separate `event_name` and `verifier_kind` names and a positional-only event-name writer argument. A regression test deliberately injects the old collision error and proves that even this writer failure cannot prevent the underlying call. Start, finish and result recording each fail independently without modifying the original outcome.

Real A/B comparisons use the same `hive.targeted_verify` entry point and host external context, candidate bytes, frozen tests, image, deadlines and NFRT attestation. Comparison ignores only explicitly nondeterministic paths, IDs, timestamps and logs; PASS/FAIL, check names/results, case/failure identities, timeouts and source integrity must agree. Native verifier invocation files/events are required; wrapper events alone are not invocation proof.
