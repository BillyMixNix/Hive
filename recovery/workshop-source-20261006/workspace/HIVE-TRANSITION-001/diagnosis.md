# Diagnosis and falsifiable repair hypothesis

Recorded before production edits. See reconstruction.md and failure-taxonomy.json for complete source and artifact references.

**Symptom:** planner correction exhaustion in 14/16 trials. **Supported causal interface defect:** the host knows an exact write boundary, but does not carry it into planner generation schemas or complete first-attempt feedback. `_normalize_plan` raises before `_validate_host_write_scope`, hiding an already-present scope violation in 11/14 initial rejected plans. In the eight qwen2.5 trials, correction specifically mandates a nonempty interface contract based on an unauthorized tests assignment. The model follows that diagnostic and retains the scope violation. This is a reproducible controller feedback defect, not evidence that arbitrary test writes should be permitted.

The smallest repair under test is to carry that same existing host boundary into planner schema path enums and collect normalized path scope violations alongside plan issues before asking for the single correction. Scope-aware corrections may deactivate unauthorized roles; the normal validator must still reject a missing contract when multiple roles remain active. Explicitly advertise the existing canonical inactive goal `no change needed` in the host boundary text. Do not expand the accepted plan language, strip invalid fields, drop unauthorized assignments, synthesize a plan, expand budgets, modify worker operations, or change verification.

This mechanism covers the exact 8/16 recurring class and provides earlier scope feedback for three more initial failures. It is not a demonstrated explanation of all failures. The six inactive-role failures expose a related representation issue: `_no_change_goal` does not recognize prose such as `No UI changes required` even with empty files/criteria. This repair clarifies the spelling rather than accepting additional ambiguous prose. The two worker failures demonstrate a separate source-anchor grounding problem.

Historical raw plans must remain rejected. A valid equivalent plan should dispatch backend, and malformed/scope-violating corrections must still terminate before workers. The live diagnostic is one new J001 trial with the same model, baseline, write files and deterministic gates. It measures transition reachability and cannot estimate success rates or establish Hive superiority.

## Evidence-triggered tightening after the first diagnostic

Revision 1 exposed a preexisting ownership hole: the constrained planner put the same allowed path in backend and tests, then added a contract. Both the frozen validator and revision 1 accept the corrected overlap, despite the existing prompt claiming cross-role overlap is rejected. Dispatch through this plan is not evidence of a valid planning transition. See `live-revision1.md` and `evidence/differential-plan-replay.json`.

The final repair also rejects duplicate file ownership and includes that violation in correction feedback. This strengthens an advertised invariant without inferring repository-specific roles or adding any J001 implementation detail. The corrected role set remains model-produced. All 30 factorial decisions stay unchanged, and the newly exposed overlapping diagnostic plan becomes rejected. The final suite records 237 passed and two platform symlink skips. A second separately frozen diagnostic tests this final source revision; the original diagnostic, original source revision, and original freeze remain preserved.

Falsification criterion for the ownership finding: the exact revision-1 corrected plan would have to fail the frozen normalizer/host checks, or it would have to assign distinct paths. Differential replay demonstrates neither. A valid distinct-file multi-role plan must continue to pass with a linking contract, which is covered by the unchanged role/responsibility tests.
