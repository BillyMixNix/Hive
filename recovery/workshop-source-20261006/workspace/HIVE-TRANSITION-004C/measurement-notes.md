# Measurement notes

- No Ollama/model-generation requests are used by the 004C harness. Every JVM run uses a fresh source clone and private container cache; there is no promotion path.
- `seeded-baseline` failed closed before Gradle because the newly added seed helper used `hashlib.file_digest`, unavailable in the pinned image's Python 3.10.12. It remains preserved as an integration failure. Streaming SHA-256 replaced that API; a pinned-image smoke check and 30 deterministic seed tests then passed. `seeded-baseline-02` is the corrected baseline control.
- Initial JVM sampling searched entire command strings, so the diagnostic Python process matched its own embedded Java command text after sampling the actual Gradle daemon. The extra attempted attach timed out after four seconds and did not modify the build. Actual daemon thread dumps were retained. This diagnostic selection defect is corrected before final replays; no initial measurement is erased.
- Cache-integrity scans run before/after bounded verification, not concurrently with it. Only small source/evidence reads and bounded process/mount observations occur during timed controls. Host preflight/postflight duration is separate from the 240-second Docker subprocess budget.
- `jcmd Thread.print` performs a brief JVM attach/safepoint. It is labeled observation, and cannot grant acceptance. Remaining timing effects are a measurement limitation rather than assumed zero.
- The complete suite wrote synthetic Workshop runtime state in the isolated checkout. The changed database and two generated snapshots were preserved under `evidence/regression/runtime-state`, then the checkout's original database was restored and those new snapshots moved out. Production/test source files were unchanged; the audit excludes runtime snapshot code using the existing source-exclusion policy. The pre-cleanup audit is retained separately.
