# Independent 001C adversarial findings — recorded before repair

The independent reviewer inspected the recovery-only diagnostic and host-bound replay code after the first deterministic gate. The findings below were recorded before the corresponding changes were made; later sections will state the repair and retest outcome.

1. **Replay cardinality gap (HIGH).** `REPLAY_ENVIRONMENT_CONTRACT.json` declares `max_replays: 1`, but the initial `run_host_bound_j001` only held a process lock. Two sequential calls in one or separate processes could each begin model execution. A durable, exclusive claim in the run storage is required before any model call; process locking alone is insufficient.
2. **Numeric XML covert channel (HIGH).** The initial safe diagnostic exposed four candidate-influenced JUnit XML integers up to 10000 without an independent consistency check. Even though these are non-textual, malicious candidate execution could encode protected data in their values. The safe model projection must omit those XML counts entirely unless independent host authentication exists. The human audit record may retain them. A host-frozen expected-case count is a different provenance class.
3. **Boolean schema-version confusion (MEDIUM).** Host `validate` compared `schema_version` with integer 1 using equality, so Python `True == 1` admitted a wrong type. The independent reviewer confirmed this with a synthetic malformed diagnostic. Require exact integer type, not truthy/equal value.
4. **Residual XML-to-enum influence (HIGH).** Removing numeric XML values from serialized output was insufficient: the first revision still used those values to choose `FROZEN_ACCEPTANCE_FAILED`. A candidate could flip a model-visible enum or force projection failure through forged XML counts. The model projection must not consult XML at all; the fixed host check result supplies only a coarse gate-failed label.
5. **Unqualified Python runtime (MEDIUM).** The host-bound preflight initially bound Docker/cache/source but did not verify the host CPython executable or required `httpx` installation recorded in the 001B manifest. Different interpreter or provider-transport bytes could pass pre-model checks. Bind the interpreter/standard-library and required package file identities, or explicitly keep readiness NO.
6. **Python startup/import-path gap (MEDIUM).** Sealing the executable, stdlib, DLLs and selected distributions still left `sys.path`, `.pth` startup hooks and user-site/customize paths unchecked. The reviewer inserted an unattested path into `sys.path` and the runtime verifier still passed. Bind the exact import-path tail, restrict the entry path to this checkout, seal startup hook bytes and their imported distribution, and reject user-site/environment overrides.

## Repair and independent retest

The replay now uses an atomic persistent one-shot claim at the fixed approved run root; a second call fails before model execution. The projection no longer reads JUnit XML numbers for either fields or enum selection. Exact integer typing rejects a boolean schema version. The host-bound preflight hashes the Python executable, DLL, standard library, required distribution files, import-path tail and startup hooks, and rejects user-site or startup environment overrides. Recovery tests exercise these rejection paths. The 001B environment verifier still checks all 4,866 selected cache files; the 001C wrapper checks the entire 4,873-file layout and invokes Docker by the verified immutable image ID. Promotion remains unavailable.

After those changes, the independent reviewer repeated the injected `sys.path` probe. It failed with `ValueError: host Python runtime differs from sealed 001C identity`. The reviewer found no remaining demonstrated HIGH or MEDIUM bypass within the bounded host-bound entrypoint. A privileged actor who can alter this host after attestation or delete the claim is outside the trusted-host contract. Portable reconstruction remains unproven. No historical artifact or model call was involved in these findings or retests.
