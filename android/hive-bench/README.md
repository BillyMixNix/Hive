# Hive Bench Android v0.1

Hive Bench turns an Android phone into a local Raw-vs-Hive test rig.

## Product law

> Human language is preserved. Machine state is compressed. Source remains recoverable.

The APK is built on the upstream `llama.cpp` Android binding pinned to commit
`c841aeeb8bb2fe417038dadfa9b007cf1a9ef950`. The build patches the sample's
context window from 8,192 to 32,768 tokens and allows up to six CPU threads so
the phone can execute the same 8k / 16k / 24k / 30k fair comparison used by
Hive validation.

## Model

Use the official Qwen GGUF:

- repository: `Qwen/Qwen2.5-Coder-3B-Instruct-GGUF`
- file: `qwen2.5-coder-3b-instruct-q4_k_m.gguf`
- approximate size: 2.1 GB

The model is selected through Android's document picker and copied once into
app-private storage. No provider API key is used.

## What the app measures

For each selected context size it runs the same model on:

1. Raw accumulated coding-agent history.
2. Hive model-facing context generated by `adapt_coding_session`.

Before every measured prompt, the llama.cpp conversation/KV state is reset by
setting the benchmark system prompt. The app records:

- expected-answer pass/fail
- precomputed Qwen tokenizer prompt count
- wall-clock inference time
- battery temperature before/after
- available RAM before/after
- model output

The execution order alternates Raw/Hive by target to reduce systematic thermal
order bias. Results can be shared as JSON back into ChatGPT/Hive.

## Scope

This is a phone execution harness for one controlled coding task. It does not
claim that every long agent history compresses to the same size or that phone
performance predicts cloud-provider performance.

## Next hardware step

v0.1 intentionally starts with the upstream CPU-variant Android binding for a
reliable baseline. The pinned llama.cpp revision also contains current Qualcomm
Adreno/OpenCL work; an OpenCL build can be added after the baseline APK is
verified on-device.
