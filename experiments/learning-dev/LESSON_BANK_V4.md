# Final retained-lesson comparison, 8 September 2026

Goal: test whether the same `gpt-5.6-luna` model repairs fresh authored Python
projects more efficiently when given lessons that it derived from earlier public
debugging experience. This is external memory, with unchanged model weights.

The V2 development signal is exploratory. Its selected-family confirmation
stopped on HTTP 400. V3 phase 1 showed only a small call reduction; phase 2 stopped
on malformed JSON inside a valid native argument string **in the lesson arm**.
These studies remain in the record and establish no confirmed gain. V4 is a new
study, not a relabeling or continuation of those confirmation results.

## Transport and counted failures

The direct native functions constrain argument objects instead of a string
containing JSON. The original Hive executive and its authority, source-edit,
acceptance and review checks remain unchanged. Only tools offered by the initial
controller packet enter the API request. No tool executes inside the API.

A malformed/refused/incomplete model answer with fully settled usage consumes
that recipient as an unsuccessful repair, scored at the full 36-call allocation.
The failed response is neither repaired nor retried. Each different recipient
starts a fresh exclusive request journal carrying the predecessor's entire charge.
HTTP errors, unknown usage, unsupported contracts, corrupted workspaces, or failed
evaluation integrity stop the study. These are not counted as successful repairs.

## Formation, frozen before confirmation

Use the three families selected by the original V2 development rule. For each,
select the slowest completed, successful lesson-arm V3 recipient; ties use case ID.
The proposer receives its original public source, verified broker observations,
candidate public source and parent lesson. Observation text is clipped at 1,500
characters. It receives no reference repair or acceptance/protected test body,
score, or confirmation case. It generates one revised general lesson per family
in one request. No human edits or selection among multiple proposals are allowed.
All three lessons are frozen by a hash in the phase-0 artifact and supplied together
to every lesson-arm recipient. A preceding single native-call diagnostic uses the
old failing packet; its returned action is preserved unexecuted and earns no repair
or learning credit. Total formation/diagnostic allowance: four model calls.

## Confirmation sample and assignment

The exact fixtures and grading code are committed before formation. There are
18 new projects: six each for paired sorting, single-use iterables and cache
identity, variants 42–47. Each family has three structural templates, each
represented twice. Two separate inclusive-boundary projects assess retention.
Fresh names and values do not make these independent real-world defect families;
any finding is conditional on this small authored task distribution.

Each project runs once in each of three fresh controllers:

* Baseline: no historical lessons.
* Lesson: the complete frozen three-lesson bank.
* Neutral: three unrelated archival passages, word-matched to the lesson fields.

All receive the same public source, goal, model alias, tool constraints, 36-call
allowance, 4,096-output-token limit, and independent acceptance/protected tests.
The bank is never updated from confirmation feedback. A fixed seeded shuffle
interleaves arms within phases. Phases 1–3 contain six transfer projects each;
phase 4 contains both retention projects. No recipient is replayed, dropped, or
substituted. There is no early positive decision or extension based on results.

## Decision, frozen in advance

The primary score is calls to independently verified repair. An unsuccessful
repair receives 36; this penalty is a utility score, not a billed charge. To declare
`CONFIRMED_GAIN`, all 18 lesson repairs and both lesson retention repairs must pass,
and the lesson arm must reduce mean penalized calls by at least 15% against **both**
controls, with exact one-sided paired sign-flip p ≤ 0.00625 for each comparison.
The alpha allocation is smaller than the previous .025 and .0125 attempts; their
sum plus this attempt is .04375. Otherwise report `GAIN_NOT_CONFIRMED`, or
`INCOMPLETE`/`INVALID` if the required sample or integrity is missing.

Report all raw accuracy, actual calls, measured tokens and conservative API costs
alongside the primary score. Do not claim fine-tuning, weight improvement, general
intelligence improvement, or recursive self-improvement from this experiment.
